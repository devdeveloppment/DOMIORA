# DOMIORA Remote MCP Server

DOMIORA now includes a separate, deployable MCP service in `mcp_server/`. It does not expose the Django database or files. The only tool currently exposed is `ask_claude`.

## Architecture

```text
MCP-compatible agent
        | Streamable HTTP + MCP bearer token
        v
Render: domiora-mcp
  auth, validation, size limits, rate limit, request logs
        | HTTPS + server-only ANTHROPIC_API_KEY
        v
Anthropic Messages API / Claude
```

This service is a real MCP server using the official Python MCP SDK and the current Streamable HTTP transport. It is not a JSON endpoint pretending to be MCP.

## Local run

From the repository root:

```powershell
$env:ANTHROPIC_API_KEY = "paste-a-new-server-key-here"
$env:MCP_ACCESS_TOKEN = "generate-a-different-client-token"
$env:MCP_PUBLIC_URL = "http://127.0.0.1:8000/mcp"
$env:MCP_ISSUER_URL = "https://tokens.example.invalid"
.\.venv\Scripts\python.exe -m uvicorn mcp_server.server:app --host 127.0.0.1 --port 8000
```

`MCP_ACCESS_TOKEN` is a client credential and must be different from `ANTHROPIC_API_KEY`. The current static verifier supports one or more comma-separated tokens. For a large multi-tenant deployment, replace it with a JWT or introspection verifier backed by an identity provider.

Health check:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

The MCP endpoint is `http://127.0.0.1:8000/mcp`. The service advertises the tool through standard MCP `tools/list` and executes it through standard `tools/call`.

## Client configuration

Copy [mcp_server/client-config.example.json](mcp_server/client-config.example.json) into the configuration format of the MCP host and replace only `REPLACE_WITH_MCP_ACCESS_TOKEN`. Never put `ANTHROPIC_API_KEY` in the client configuration.

For the deployed Render service, use:

```json
{
  "mcpServers": {
    "domiora-claude-cloud": {
      "url": "https://domiora-mcp.onrender.com/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_ACCESS_TOKEN"
      }
    }
  }
}
```

The URL remains a placeholder until Render has created the service and its real hostname is known.

## Render deployment

1. Revoke every API key that was previously pasted into chat, local Claude settings, examples, or scripts. Create a new Anthropic key.
2. Commit and push the code, but never commit `.env` or `.claude/settings.local.json`.
3. In Render, create the Blueprint from `render.yaml`, or create a second Python web service for this repository.
4. Set these secret environment variables on `domiora-mcp` in Render: `ANTHROPIC_API_KEY`, `MCP_ACCESS_TOKEN`, and `MCP_ISSUER_URL`.
5. Set `MCP_PUBLIC_URL` to the exact HTTPS URL ending in `/mcp` generated by Render. Keep the `MCP_PUBLIC_URL` host aligned with the Render service hostname.
6. Confirm `GET /health` returns `{"status":"ok","service":"mcp-server"}`.
7. Configure the client with that URL and the MCP access token.

Render terminates HTTPS. Uvicorn is started with proxy headers, and the MCP SDK host allowlist prevents DNS-rebinding requests. The current rate limit is process-local; keep one instance or put a shared gateway such as Render's edge/WAF in front for fleet-wide quotas.

The same service can be built with `mcp_server/Dockerfile`:

```powershell
docker build -f mcp_server/Dockerfile -t domiora-mcp .
docker run --rm -p 8000:8000 --env-file .env mcp_server
```

## `ask_claude`

Input:

```json
{
  "prompt": "Analyse cette erreur",
  "context": "Contexte explicitement sélectionné par l'agent",
  "model": "claude-sonnet-4-20250514",
  "max_tokens": 1024
}
```

The service forwards only the supplied prompt and context. It never scans the repository automatically. Input limits, model-name validation, timeout, no automatic retry, and a token cap are enforced before the Anthropic call. Errors returned to the MCP client are generic; logs contain only error type, request id, duration, sizes, and model name.

## Authentication and secrets

The service is an OAuth-style resource server: it verifies a bearer token but does not issue tokens. The current deployment uses operator-managed static bearer tokens from `MCP_ACCESS_TOKEN`; use a real authorization server/JWT verifier before opening the service to many users. `/health` is intentionally public and reveals no configuration state.

`ANTHROPIC_API_KEY` is server-only. It is stored as a Render secret, read from the process environment, and never sent to the MCP client or written to logs. `.env.example` contains placeholders only. The former key in `.claude/settings.local.json` has been removed, but it must still be revoked because it was exposed previously.

## Fallback and billing

The chain is:

```text
Agent or Copilot host -> DOMIORA MCP -> Anthropic API -> Claude
```

An MCP host may choose to call this tool when it is available, but MCP does not automatically extend or bypass GitHub Copilot model, context, quota, policy, or plan limits. Any fallback policy must be configured by the host/agent, if that host supports tool routing. This server cannot force Copilot to route a response through it.

Anthropic calls made with `ANTHROPIC_API_KEY` are billed to the Anthropic API account owning that key. They are separate from GitHub Copilot billing and quota.

## Tests and audit

Run:

```powershell
.\.venv\Scripts\python.exe -m pytest mcp_server/test_server.py -q
```

The tests cover MCP tool discovery, mocked Claude calls, health, bearer rejection, token verification, and oversized prompts. The real Anthropic call is deliberately not made by tests. A production smoke test should use a newly rotated key and a small prompt after Render deployment.

Known limitations:

- The static token verifier is suitable for a controlled first deployment, not a full user identity platform.
- Rate limiting is per process; use a shared edge limiter for multiple replicas.
- The repository still contains other unrelated credential-shaped or hardcoded secrets identified by the audit. Rotate them and run secret scanning before publishing the repository.
- A cloud URL cannot be proven from this local workspace until the Render service is actually created and deployed.
